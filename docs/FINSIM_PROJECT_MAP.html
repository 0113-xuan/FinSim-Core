1. 這個專案在做什麼？

幫人在「花大錢之前」先試算：買了會怎樣？

使用者填入收入、存款、每月開銷，再選一台想買的車。系統算出未來 5 年（60 個月）每個月的存款變化，並做壓力測試。目前以買車當示範案例。

研究問題：如何把重大財務決策轉成「可追溯的現金流情境」，用基準比較、壓力測試與限制搜尋，幫助使用者理解決策的財務影響？

60 個月每次試算的期間
7 版本 / 4 車系推薦用車款（附官方來源）
500 + 154自動測試通過（Python + Node）
34 / 56真實 Gemini 呼叫有回應

運作方式（四步）

① 你填資料、說出需求
→
② 網頁收集並顯示結果
→
③ 計算機真正算錢的地方
→
④ 結果每月存款、風險、比較
🤖 AI 小助手（可有可無）

只負責「聽懂」你打的字，例如「我不喜歡休旅車，但常載長輩」，整理成選項讓你確認。它不算錢、不替你決定；每一項都要你點頭才算數。AI 壞掉時其他功能照常使用。

為什麼這樣設計？AI 有時會講錯，錢不能讓它亂算。所以「算錢」交給固定規則的計算機：同樣輸入一定得到同樣答案，也能逐項檢查。

2. 使用者現在可以做什麼？

🚗 功能一：幫我選車

  • 三頁問卷（預算、用途、偏好），可返回修改
  • 可用一句話補充需求（AI 協助，選用）
  • 列出適合的車，並說明為什麼不適合其他車
  • 資料不足的車寫「資料不足」，不亂猜
  • 挑一台，看 5 年財務影響

🧮 功能二：直接購車試算

  • 已知要買哪台，直接試算買車前後 5 年存款
  • 壓力測試：收入 −10%、失業 3 個月、突發支出 10 萬、利率 +2 個百分點
  • 「如果油價漲了？」一次改一個條件
  • 方案 A / B 並排比較；找出「最高買得起的車價」

使用流程（進階）

兩條路線互通：頁首可切換「幫我選車／直接購車試算」，推薦結果可帶入單車／雙車分析。

路線 A：幫我選車

1三步問卷基本條件／用車與財務／自由補充。財務選填。
2AI 分析（選用）自由文字 → 候選需求，逐項接受／拒絕；失敗可略過。
3確認需求改任何答案，確認與 AI 候選都會失效，需重新確認。
4規則推薦符合／不符合／資料不足三態；最多列出前幾名。
5五年財務分析每月支出、最低現金、預備金、限制是否通過。

路線 B：直接購車試算

1填財務＋車款收入、存款、支出、既有月付；車價、頭期、利率、期數。
2確認假設每個假設標示來源、單位、是否被覆寫。
360 個月比較買車前 vs 後、最低現金、預備金、價格上限。
4壓力測試四種壞情境，各自顯示通過與否。
5What-if / A·B一次改一個因素；存方案 A 再算 B。

6. 目前要注意的事

① AI 還不穩

不要對外說「AI 很穩」。可以說「AI 是輔助，壞了也不影響主要功能」。

② 資料不算多

目前只有 7 個車款版本；價格是官方標價，不是成交價。簡報要講清楚。

③ 有些數字是「假設」

保險、稅金、保養、油價是規劃值，不是市場報價；畫面上都有標示。

項目狀況做法
無存取控制AI 端點不需登入；限流為各 worker 記憶體內 IP 計數公開網址＋真實 Key 會被消耗額度；部署需網路層限制
語意誤判模型可能把含糊句抽成明確條件人工逐項確認是安全防線，不代表模型已修好
簽章金鑰未設固定 CAR_NEEDS_SIGNING_KEY 時，重啟／換 worker 會讓 AI 候選失效多 worker 部署須設共同的 ≥32 bytes 金鑰（不與 JWT 共用）
暫存狀態使用者、草稿存在記憶體；重啟即清空demo 不需要；之後持久化再上資料庫
文件未追蹤多份審查與工作報告目前是 Git 未追蹤檔合併或交接前決定哪些要提交
README 偏舊AI 段落仍以 OpenAI 風格描述，未涵蓋 P1–P4以本頁與 P4_TEAM_TEST_GUIDE.md 為準

最近一次：Python 500 passed、Node 154 passed，預設不呼叫真實模型。要開 AI：設 AI_PROVIDER=gemini、GEMINI_API_KEY、AI_ENABLED=true（一般點擊也會花額度）。

給 AI 助手的規則

  • 金額只在後端算；前端不放財務公式；AI 不算錢、不推薦車款。
  • AI 是選用的：失敗（逾時／格式錯／停用）時仍須能走完「問卷 → 推薦 → 財務分析」。
  • 缺資料不可用 0 代替（例：Model 3 無可核對電耗 → 顯示「資料不足」）。
  • 改計算前先跑 tests/fixtures/p0/vehicle_api_snapshots.json 快照回歸。
  • 不提交 .env 或任何 Key；不把「有回應」寫成「語意正確」，也不把 Mock 通過率寫成模型準確率。

名詞小字典

後端／計算機
在使用者看不到的地方，負責真正算錢的程式。
確定性
同樣的輸入，一定得到同樣的答案（AI 不是這樣，所以不讓它算錢）。
壓力測試
