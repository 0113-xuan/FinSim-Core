# Codex 任務：planner 拆成多個頁面（登入、財務資料、儀表板、計畫、個人資料）

日期：2026-11-01。完成後由 Claude 審查。

**前置條件**：`docs/CODEX_TASK_PLANNER_VEHICLE_2026-11-01.md`（購車事件）必須已經完成並通過審查。這份任務的計畫頁會用到購車事件的表單和結果。

## 背景

- 目前 `static/planner.html` 是一個長頁面，登入、財務資料、貸款、計畫、事件、模擬結果全部擠在一起。
- 新的流程：
  1. 登入。
  2. 第一次使用的人先到獨立頁面填財務資料。
  3. 進入儀表板，看到自己的資產、負債，以及每個計畫的走勢。
  4. 點進計畫設定事件，看模擬結果。
  5. 隨時可以到個人資料頁修改財務資料和貸款。
- 版面參考常見的理財工具：左側選單、儀表板上方是淨值、資產、負債三張卡片，下方是計畫卡片。**只參考版面結構，不要模仿任何現有產品的名稱、商標、配色或文字。**名稱一律用 FutureWallet，顏色沿用 `static/style.css` 的變數。
- 這次不改後端計算，也不改資料庫結構。

## 任務 A：共用外框 `static/shell.js`、`static/shell.css`

- **Supabase 初始化**：沿用現在的做法，讀 `/config/public` 後建立 client。supabase-js 維持 `@2.45.4`。
- **登入檢查**：除了 `login.html`，每一頁載入時都要檢查 session，沒有登入就導到 `login.html`。
- **財務資料檢查**：已登入但還沒有 `profiles` 資料時，除了 `onboarding.html` 以外的頁面都要導到 `onboarding.html`。
- **左側選單**：
  - FutureWallet、儀表板、目前財務狀況（個人資料頁）。
  - 「計畫」分組列出使用者的每個計畫，點了進入該計畫頁；分組最後是「新增計畫」。
  - 最下方是登出。
  - 目前所在的頁面要有選取狀態。
- **手機版**：寬度 760px 以下時，選單收成左上角的按鈕，點開變成抽屜，不可以出現橫向捲動。
- **資料存取**：把 `planner.js` 的 `createStore` 搬到共用模組，所有頁面共用同一套讀寫邏輯。每次寫入都要帶 `user_id`，這點和現在一樣。另外補上：
  - `updateEvent`：修改事件。
  - `updatePlan`：改計畫名稱。
- 錯誤一律顯示在畫面上，不能只寫進 console。

## 任務 B：頁面

### `login.html`：登入

- 用 email 和密碼登入、註冊。註冊後如果需要確認信，要提示使用者。
- 登入後依有沒有財務資料，導到 `onboarding.html` 或 `dashboard.html`。

### `onboarding.html`：第一次填財務資料

依序分成四組：

1. **收入與支出**：每月實領收入、固定支出、變動支出。
2. **現金與投資**：可動用現金、投資目前市值、每月投資金額。
3. **現有貸款**：可以新增多筆，也可以一筆都沒有。
4. **偏好**：年調薪率（留空代表跟著通膨）、預備金目標月數（預設 6）。

每個欄位都要有一句白話說明，例如「每月實領收入：扣掉勞健保、稅之後實際入帳的金額」。儲存後導到 `dashboard.html`。

### `dashboard.html`：儀表板

**上方三張卡片**

| 卡片 | 內容 |
| --- | --- |
| 資產 | 現金、投資市值，以及兩者合計 |
| 負債 | 每筆貸款的每月還款與剩餘期數；剩餘應還總額＝每月還款 × 剩餘期數，並註明「未扣除利息折現」；沒有貸款時顯示「目前沒有貸款」 |
| 淨值 | 資產合計減去剩餘應還總額，旁邊用一句話說明算法 |

**下方計畫卡片**

- 每個計畫一張卡片，顯示：
  - 計畫名稱、事件數量。
  - 一條小走勢圖：240 個月確定性模擬的淨資產。
  - 期末淨資產。
  - 第一次現金小於 0 的月份，沒有就顯示「未出現」。
- 走勢圖上用小圓點標出事件發生的月份。
- 小走勢圖用 `/simulate` 跑就好，不要在儀表板上跑 Monte Carlo。
- 最後一張是「新增計畫」卡片，點了可以輸入計畫名稱並建立，建立完成後進入該計畫頁。

### `plan.html?id=<plan_id>`：計畫頁

- **上方**：計畫名稱（可以修改）、刪除計畫。
- **事件時間軸**：依開始月份排序，每筆顯示類型圖示、名稱、月份和金額摘要，可以修改、刪除。新增事件的表單沿用現在的四種類型：一次性、期間每月、換工作、購車。購車的欄位與「購車分析」按鈕照前一個任務的做法，但購車分析的結果要整理成三組，各有小標題：
  - **財務限制**：是否全部通過。
  - **購車成本**：每月車貸、總利息、購車當月一次支出、最低現金、最高可負擔車價。
  - **壓力測試**：收入減少、失業、突發支出、貸款利率上升，各自是否通過。另外加一句說明：「壓力測試是在原本條件上再加壓，未通過代表遇到這種情況時現金會低於你設定的限制。」

  現在這些結果擠在同一行，「財務限制：全部通過」和「收入減少：未通過」放在一起容易讓人誤會。
- **模擬結果**：
  - 期間選擇（60、120、240 個月）和「執行模擬」按鈕。
  - 一張折線圖：確定性模擬的現金與淨資產，橫軸用 YYYY-MM，事件月份用標記標出。
  - 現在 planner 的所有指標卡片、說明文字、資料來源、警告、購車小節，全部保留。
- 網址中的 id 不存在或不屬於這個使用者時，顯示「找不到這個計畫」，並附上回儀表板的連結。

### `profile.html`：目前財務狀況（個人資料）

- 修改財務資料：欄位和 onboarding 相同，用 upsert 儲存。
- 貸款：新增、刪除。
- 顯示登入的 email，並提供登出。

改成只把使用者導到 `login.html`，不要再保留兩套介面。`planner-model.js` 繼續沿用。
