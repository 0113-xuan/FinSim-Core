## 敏感度分析

`POST /decisions/vehicle/sensitivity`，請求沿用 `VehicleDecisionRequest`。

每次只改一個因素，其他條件維持不變。列出完整指標與限制，主圖呈現五年期末現金相對原方案的差額。

| 因素 | 較低與較高端點 |
|---|---|
| 收入 | -10% / +10% |
| 油電、停車、保險 | -20% / +20% |
| 維護 | -30% / +30% |
| 通膨 | -1 / +1 個百分點；下限 0，實際端點會回傳 |
| 車價 | -10% / +10%；頭期款固定 |

排序依兩個有效端點的期末現金差額範圍，反映所選變動幅度，不能解讀為發生機率、因果關係或標準化重要性。
若端點超出金額或貸款限制，明確回傳 `not_applicable`，不偷偷修改頭期款或捏造結果。
沒有兩個有效端點的因素不進入完整範圍排名，但保留於數值表。

### 易懂式敏感度與自訂變化

敏感度主畫面改為「如果條件改變，會怎樣？」。一次選一個因素，呈現實際金額變化、五年後現金的前後值、最低現金與購車生效月結餘，以及是否符合使用者設定的限制。失敗時列出實際值與門檻，不使用「安全」或發生機率等未被模型支持的判斷。

原 Tornado 圖與完整明細預設收合，展開時才建立圖表。

`POST /decisions/vehicle/what-if` 包含 `request`（原購車請求）、`field`（`salary`、`monthly_parking`、`purchase_price`）、`change`（有正負號的台幣差額）。收入調整從模擬第1月起，停車費從購車月起；車價變化維持原頭期與期數。後端使用與固定幅度敏感度相同的變化評估函式。

非法端點回傳 `not_applicable`、空財務結果及理由；未知欄位、非有限差額由 schema 拒絕。不覆寫原方案與方案 A。

驗證包括月收入減少5,000元且薪資成長率0時，60個月期末現金減少300,000元；零通膨下每月停車費增加1,000元且第1月購車時，期末現金減少60,000元。實際瀏覽器已驗證條件選擇、折疊圖表、自訂變化、非法購車金額、手機版與修改後清除舊結果。

本次易懂式介面更新驗證：Python 279 項通過（2 則既有 JWT 測試金鑰長度警告）；Node 49 項通過。桌面與390px手機版無前端執行錯誤或整頁橫向溢出。

## A/B 比較

`POST /decisions/vehicle/compare`，請求包含完整 `a` 與 `b`。

- 相同財務資料、基準月份、財務限制；不一致回傳 422。
- 可改車價、購買日期、付款方式、頭期款、利率、期數及持有成本。
- A/B 使用同一套購車評估、壓力測試、車價上限搜尋。
- 差額由後端計算，方向為 B 減 A；不自動推薦勝出方案。
- 前端保留的是已確認並成功評估的請求快照，只保留於目前分頁，不持久化。
- 修改資料後須重新確認並評估；財務條件變更時禁止拿舊 A 比較。
- 共用 60 個月觀察期。延後購買會少付部分貸款，但可能仍有未償本金，不應把較高期末現金解讀為較高淨資產。

## 債務到期

`profile.existing_debts` 可選，每筆包含 `name`、`monthly_payment`、`remaining_months`。
剩餘期數從基準月份後的第 1 個模擬月起算，期數 14 表示第 14 月仍付款，第 15 月停止；0 表示已結清。

明細與非零 `required_monthly_debt` 不能同時使用。未提供明細時保留原本全期固定總額行為。
新車貸獨立計算；基準、購車、壓力、敏感度、比較及車價搜尋都會使用同一既有債務時間表。

## 假設校準紀錄

紀錄包含 `value`、`default_value`、`unit`、`source`、`source_date`、`description`、`user_override`、`reference`、`reviewed_at`、`registry_version`、`calibration_status`。

目前完成的是紀錄與透明呈現的基礎。預設值仍是 `planning_assumption`；尚未完成外部資料校準。
沒有官方資料或報價依據時，`reference` 與 `source_date` 保留 null；2026-10-10 是版本檢視日期，不是市場資料日期。
使用者的值與覆寫狀態會隨評估結果回傳。後續校準需另行確定車種、排氣量、使用地區與保險條件，再補可支持對應值的來源。

## 驗證方式

- 後端：債務最後一期與停止月、禁止重複扣款、舊輸入相容、敏感度定值與方向、排序、非法端點、零通膨、相同方案差額為零、延後購買、共用條件與來源。
- 前端：快照不被外部修改、不同財務條件拒絕比較、資料修改取消分析、舊圖表銷毀、非法端點不顯示數字。
- 實際瀏覽器：學貸 8,000／14 期，第 15 月停止；七因素圖表；650,000 vs 750,000 車價比較；財務資料變更後禁用舊 A；桌面及手機排版。
- 自動測試不需要真實 AI key。

本輪驗證：Python 276 項通過（2 則既有 JWT 測試金鑰長度警告）；Node 46 項通過。
瀏覽器案例中，車價 650,000 與 750,000 的五年期末現金差額為 -107,811.60；敏感度七項完整，最大幅度為收入；無前端執行錯誤，390px 手機版無整頁橫向溢出。

## 養車成本摘要（2026-10-11）

購車 API 新增向後相容的 `ownership_costs`，沿用建立情境時的成本事件及引擎逐月取位規則。前端分開顯示每月養車、含車貸的每月淨增加、購車當下付款及觀察期累計支出。交通抵減為負項，車貸含本金與利息，不另加車價；明細列出逐月取位差額。延後購車只計觀察期內持有成本，超過觀察期的車貸顯示剩餘期數。舊回應沒有此欄位時隱藏摘要。
