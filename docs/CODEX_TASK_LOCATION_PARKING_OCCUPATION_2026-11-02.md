**分兩個階段做**：

- **第二階段**：任務 D 到 E（職業、薪資參考）。

## 背景

- 專題的目標是「更個人化、更可信」。目前財務資料只有金額，系統不知道使用者住在哪裡、做什麼工作，所以：
  - 購車的停車費只能用固定的 2,000／月。
  - 換工作事件只能讓使用者自己猜新薪水。
- **這次的改法**：
  1. 財務資料新增**所在地**（縣市＋行政區，例如「臺中市 北屯區」）和**職業**。
  2. 購車時，如果使用者**沒有自己的車位**，就列出所在行政區的停車場，以及它們的收費資訊（有月租價就顯示月租價），給使用者參考並選擇。
  3. 換工作事件依職業顯示主計總處的官方薪資統計，給使用者參考。
- 原則不變：資料都要標示來源和日期，Python 負責計算和資料處理。

### 已確認的決定（使用者 2026-11-02 決定）

- **停車場資料**用交通部 TDX 的路外停車場靜態資料，下載一次存成快照，不在使用時即時查詢。
  - 第一版只做**臺中市**。其他縣市先顯示「目前只提供臺中市的停車場資料」，讓使用者自己填。
  - TDX 的欄位有 `CountyName`、`TownName`、`Address`、`FareDescription`、`SpecialOfferDescription`、`ChargeTypes`、`PositionLat`、`PositionLon`。**沒有月租欄位**，月租價要從收費說明文字裡解析。
- **職業**用在薪資參考和之後的換工作事件。**不用來自動調整車貸利率**，因為軍公教的車貸優惠沒有公開利率表。選軍公教時，車貸欄位旁只顯示一句提示：「軍公教可向銀行詢問專案車貸利率。」
- **資料庫**：`profiles` 新增 `city`、`district`、`occupation` 三個選填欄位。SQL 在 `docs/supabase/04_profiles_location_occupation.sql`，由使用者在 Supabase 執行。**不要自己修改資料庫**。

### 任務 B：停車場資料快照（臺中市）

1. **新增 `scripts/fetch_tdx_parking.py`**：下載 TDX 臺中市路外停車場的靜態資料。
   - API 文件：<https://tdx.transportdata.tw/>，路外停車場（CarPark）的縣市靜態資料。
   - **先試不登入能不能下載**。
     - 可以：直接下載。
     - 需要登入：script 從環境變數 `TDX_CLIENT_ID`、`TDX_CLIENT_SECRET` 讀取帳號（不可以讀 `.env` 檔，也不可以把 key 印出來）。你不要自己去取得帳號，把 script 寫好，在回報中說明「需要使用者註冊 TDX 並執行 script」，然後先用測試資料完成其他部分。
2. **輸出**：`data/parking/taichung_carparks.json`，每個停車場有以下欄位：
   - `id`、`name`、`district`（取 `TownName`）、`address`
   - `lat`、`lon`
   - `fare_description`：原文
   - `special_offer_description`：原文
   - `monthly_rent_twd`：解析出的月租價，解析不到就填 `null`
   - `monthly_rent_text`：解析出月租價的那一段原文，給使用者對照
   - `source_updated_at`

   另外寫 `data/parking/SOURCES.md`，說明授權（政府資料開放授權條款）和下載日期。
3. **月租解析**：寫成純函式 `parse_monthly_rent(text)`。
   - 只在原文出現「月租」「月票」「包月」「定期票」這類字眼，而且同一句有金額時才解析。
   - 有多個金額時（例如「日間月票 2,000 元、全日月票 3,500 元」），取**全日或最高的那個**，並保留原文。
   - 「每小時 30 元」「計次 50 元」這類計時或計次費率**不可以**被當成月租。
   - 要針對真實資料裡常見的寫法寫測試。從下載的資料中挑至少 10 種不同寫法放進測試；還沒有真實資料時，先用合理的範例，並在回報中說明。
4. **新增 `GET /planner/parking?city=臺中市&district=北屯區`**，回傳：
   - `lots`：該行政區的停車場。有月租價的排前面，再依名稱排序，最多 30 筆。
   - `monthly_rent_stats`：該區解析出月租價的停車場數量、中位數、最低值、最高值。少於 3 筆時不提供中位數。
   - `source`：資料來源、授權和快照日期。
   - `supported`：是否有這個縣市的資料。非臺中市回傳 `false` 和說明文字。

### 任務 D0（P2，先做，單獨一個 commit）：「1400元/月租」要解析成 1400

上一個 commit `0d1a29a` 為了不把「年租:16000元 / 月租:1500元」解析成 16000，讓「/月」後面緊接「租、繳、票」時一律不算月單位。副作用是花蓮縣**吉安站前停車場**的原文 `10元/半小時，1400元/月租，150元/天(00-24)，充電費率每度/8元` 變成 `null`，但它的 1400 確實是月租。

**修正方式**：在 `app/parking.py` 的 `suffix_month` 判斷，只有當「月租／月繳／月票」後面**緊接著另一個金額**時（中間可以有空白、全形或半形冒號、`NT$`、`$`），才不把這個「/月」算成前一個金額的月單位。例如：

| 原文 | 應解析出的月租 |
| --- | --- |
| `10元/半小時，1400元/月租，150元/天(00-24)，充電費率每度/8元` | 1400 |
| `年租:16000元 / 月租:1500元` | 1500（維持） |
| `16000元 / 月租:1500元` | 1500（維持） |
| `16000元 / 月繳 1500元` | 1500 |
| `16000元 / 月票：1500元` | 1500 |

- 把 `tests/test_parking_multi_city.py` 裡現在預期 `None` 的「1400元/月租」那一例改成 1400，並加上表格裡的新例子。
- 用 `python scripts/fetch_tdx_parking.py --from-dir data/parking/raw/tdx` 離線重建快照，**不呼叫 TDX**。
- 更新 `data/parking/SOURCES.md`：

  - 說明段落「/月後面緊接租繳票」的描述要改成新規則。
- 其他既有測試（含 19 個真實寫法、5 個年租季租例子、機車排除）全部維持原本結果。若有任何一個改變，停下來回報，不要改測試去配合。
