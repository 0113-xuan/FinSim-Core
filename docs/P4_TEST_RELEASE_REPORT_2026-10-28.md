## 逾時原因：事實與推論

- **已確認**：舊 alias 實際就是 3.5；原先最多 3 次嘗試，但慢初次請求通常先被 20 秒服務 deadline 取消，而 HTTP timeout 是 30 秒。
- **已確認**：本輪 56 筆沒有重複 HTTP 嘗試，兩輪逾時率相同；重試不是本次 22 次逾時的成因。
- **已確認**：多數成功請求等待發生在 headers 到達前，body 讀取通常遠小於總耗時。
- **尚不能確認**：非串流 REST 無獨立模型生成時間，不能拆開網路、服務端排隊及生成。不能直接把慢回應全歸因於 LLM。
- **尚不能確認**：相較舊輪的變化同時受時段、負載、固定 endpoint、零 retry 與 token cap 影響，不能宣稱是固定版本單獨造成改善。
